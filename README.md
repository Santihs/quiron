# quiron

A knowledge model layered on top of Obsidian vaults used with Anki. Anki
schedules cards; quiron models concepts, evidence, doubts, and coverage. See
`Quiron.md` for the v7 design, implementation status, and pending gaps, and
`DECISIONS.md` for the decisions made while implementing each phase.

## Usage

```
uv sync
uv run quiron seed --vault ../karpathy-path          # seed/refresh knowledge.json
uv run quiron capture-scan --vault ../karpathy-path   # new callouts -> inbox.jsonl
uv run quiron inbox --vault ../karpathy-path --apply proposals.json  # apply classified captures
uv run quiron today --vault ../karpathy-path          # the only command you need to remember
uv run quiron cards --vault ../karpathy-path --decide      # retention decision walker
uv run quiron cards --vault ../karpathy-path --list-gaps   # needed-but-empty concepts
uv run quiron doctor --vault ../karpathy-path --json  # findings: dangling refs, orphans, loose doubts
uv run quiron migrate --vault ../karpathy-path        # scaffold/sync Claude Code + OpenCode prompt plumbing
```

`seed` and `capture-scan` are idempotent — running them again never
duplicates or overwrites what you already generated by hand (`evidence`,
`doubts`, `card_policy`).

## Status

The current repository baseline is:

- Package version `0.1.0`.
- Persisted model `00-Meta/knowledge.json`, schema version `2` (with an explicit
  v1 upgrade path).
- Implementation through Fase 7 plus hardening: multi-vault seeding, capture/inbox
  processing, card-policy decisions, card-quality audit plumbing, evidence
  commands, parametrized reviewer templates, and `quiron migrate` for Claude
  Code and OpenCode prompt plumbing.
- Anki remains the source of truth for scheduling; quiron never persists
  scheduling fields.

The remaining design gaps are documented explicitly in the **Pending gaps**
section of `Quiron.md`. They are not implemented behavior.
